A practical, hands-on journey to build strong professional Python skills for **DevOps, SRE, automation, APIs, and production engineering**.

This repository is not a collection of copied tutorials. Every day follows the same mastery loop:

> **Understand → Predict → Code → Break → Debug → Build → Explain**

## 🎯 Mission

By Day 30, I will be able to:

- Write clean, readable, reusable Python without blindly copying code.
- Automate repetitive DevOps and SRE tasks safely.
- Work confidently with files, JSON, YAML, APIs, SQL, logs, and subprocesses.
- Build tested command-line tools and production-ready REST APIs.
- Use object-oriented programming, generators, decorators, concurrency, and async programming appropriately.
- Package, test, containerize, and deliver Python applications through CI/CD.
- Debug failures and explain Python decisions in senior-level interviews.

Thirty days is the intensive foundation—not the end of learning. The goal is measurable professional ability backed by working projects.

## 🧭 Learning Rules

1. **Type the code manually.** No blind copy-paste.
2. **Predict the output** before running important examples.
3. **Read every traceback** and identify the real failing line.
4. **Attempt each challenge first** before checking hints.
5. **Explain the solution aloud** in simple language.
6. **Commit progress daily** with a meaningful Git message.
7. A day is complete only when its code, challenge, recap, and checkpoint are finished.

## ⏱️ Daily Study Format

Recommended commitment: **90–120 focused minutes per day**.

| Block | Time | Activity |

## 🏗️ Milestone Projects

### Week 1 — Configuration Inspector

A fault-tolerant CLI that reads configuration files, validates required values, records useful logs, and explains errors clearly.

### Week 2 — Infrastructure Check Framework

An extensible, object-oriented package with generators, decorators, context managers, type validation, and comprehensive tests.

### Week 3 — Multi-Service Health Monitor

A concurrent and asynchronous monitoring tool that checks multiple endpoints, handles timeouts and retries, and produces a structured health report.

### Final Capstone — OpsPulse

**OpsPulse** will combine the entire course into one production-style Python platform:

- Load monitored services from validated YAML configuration.
- Run concurrent HTTP health checks with timeouts and retry policies.
- Classify failures and generate structured logs.
- Store incidents and check history in SQLite.
- Expose health and incident data through FastAPI.
- Run checks on a schedule and trigger notifications.
- Include unit and integration tests with useful coverage.
- Provide an installable CLI and clean project structure.
- Run through Docker and a GitHub Actions CI pipeline.
- Apply secure secret handling and graceful shutdown behavior.

**Optional stretch goal:** query a local Kubernetes/Minikube cluster and include unhealthy workload information in the report.

## 🧪 Engineering Standards

As the course progresses, all production code should aim for:

- Clear names and small, focused functions.
- Type hints on public functions and methods.
- Useful errors instead of silent failure.
- Structured logging instead of random `print()` debugging.
- Tests for important success and failure paths.
- Timeouts and bounded retries for external operations.
- No credentials, tokens, or secrets committed to Git.
- Documentation that explains both usage and design decisions.
